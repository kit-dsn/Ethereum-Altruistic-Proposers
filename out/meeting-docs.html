Reproducing mevboost.pics

Relays do implement a "Relay API" that was proposed by Flashbots. They expose an endpoint proposer_payload_delivered that "get payloads that were delivered to proposers". We scraped this endpoint and evaluated the share of these announced blocks compared to all blocks.

Initial Coinbase Address Analysis

Do we see a similar result with the coinbase addresses (i.e., addresses, where fees are passed to)?
  • We counted all proposer-coinbase pairs (there are proposers that proposed multiple blocks within our measurement period)
  • Then, we looked how many validators shared a coinbase addresses.
  • We can also look into coinbase addresses that were shared between few validators...

To get a broader overview, we can draw these values as a CDF (cumulative distribution function) — again, the x-axis denotes how many validators shared a coinbase address. The y-axis now shows the cumulative proportion over the block count. Additionally, we color the point in a linear color map of blue-red: Blue means, that none of these blocks were announced by relays, while red denotes that these blocks were all published by relays.

  • Note the logarithmic scale of the x-axis.
  • We also marked the proportion of 8.9% of blocks that are not annouced via relays (See Figure 1).

We can also plot, how many clusters (i.e., coinbase addresses) there are for each number of validators that share them.

Private Transactions

We got access to data from the project mempool.guru which tracks which blocks include private (i.e., transactions probably not announced in the mempool) transactions.

  • We compared these blocks with our records of blocks announced by relays.

We first looked how many proposers publish blocks that are (a) always, (b) sometimes, or (c) never announed by relays.
